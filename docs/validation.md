合成工单包含部署失败、孤立旧登记、GPU 子进程重启、工具权限失败、单次资源样本、未知原生故障、安装异常、集成关联，以及缺失部署事件、中途挂起后恢复、崩溃元数据待归属三种边界。

独立评估指出的修正包括：组件助手无法接受的原生部署证据有明确后续调查路径；中途不响应的样本会保留；新增崩溃文件先待归属，不直接认定主进程退出。模拟回归覆盖这些观察器行为。重启要求保留布尔类型，避免字符串 `False` 被当作真值。

观察器仍有明确限制：采样间隔内的短暂挂起可能被漏过；响应属性不能证明任务进度；摘要不保存完整崩溃文件清单、角色或挂起时序。这些需要 Codex 按工作流补充私有记录及原任务验收。

测试输出留在公开项目之外。源文件和压缩包按明确清单核对，并检查真实本机路径/会话标识、隐藏的 Skill 目录和本地文档链接。公开版沿用仓库已有的 MIT 许可及 `fly liu` 署名。

上述检查不构成多设备修复验证，也不能证明历史案例长期改善的唯一原因。真实恢复证据仍以 [历史案例](case-2026-10.md) 的范围为准。未来案例按 [贡献说明](../CONTRIBUTING.md) 扩充，保留未成功的尝试和应用更新等变量。
