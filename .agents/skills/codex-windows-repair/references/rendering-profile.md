# Rendering and cache comparisons

## Graphics

Establish the main/child process role and correlate graphics errors with reproduction. A GPU child replacement with a healthy main process does not establish a desktop crash. Use the current app's supported graphics setting or locally verified arguments for one temporary comparison, recording the prior value.

Preserve the normal package entry and effective profile. A stable direct EXE launch under a different identity/profile is not the same comparison. Choose a durable setting/driver action only after discriminating evidence and current vendor/app guidance. Do not modify drivers or global graphics settings merely because a GPU process exists. Undo a non-improving trial.

## Profile/cache

Resolve the effective active profile from actual processes and package layout. Packaged `LocalCache\Roaming\Codex\web\Codex` and unpackaged `Roaming\Codex\web\Codex` are search hints, not equivalent or exhaustive paths.

When evidence supports a cache trial, prepare independent maintenance if the host must close. Check resolved source/backup paths are inside the identified profile and explicitly chosen backup location. While the target app is closed, move only individually verified disposable rendering caches and record a manifest. Names observed in a version include `GPUCache`, `ShaderCache`, `GrShaderCache` and `DawnGraphiteCache`; verify current roles instead of treating any Cache directory as disposable.

Keep persistent browser storage, credentials, chats and projects intact. Restore only deliberately changed `Local State` properties, preserving unrelated newer properties. Never replace the whole active profile with an old backup blindly.

Verify the original workload through the normal entry. Roll back a non-improving cache trial while the app is closed, preserving regenerated entries separately before restoring backups. Document an unsuccessful comparison rather than treating cache recreation as proof of repair.

This branch has no verified cure case here. The original deployment case still crashed with GPU rendering disabled, which limits that particular experiment's usefulness without ruling out other users' graphics faults.
